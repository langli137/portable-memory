# 长期记忆（跨项目 · 所有会话通用）

> 作用域：所有项目。只放跨项目稳定复用的偏好 / 环境 / 原则。
> 项目专属的架构、字段口径、踩坑史放各自项目的记忆目录，不要写进本文件。

## 一、沟通偏好
- 中文交流。先给一句大白话结论 + 具体例子，再展开，别一次堆术语。
- 反馈要含**根因分析 + 修改逻辑解释**，便于自行验证；不要只说"改好了"。
- 习惯直接贴报错信息 / 终端输出 / 截图来定位问题，应基于证据回应，不泛泛建议。
- UI 迭代是截图驱动：截图指出问题 → 修复精确匹配视觉参考 → 回截图验证。
- 讲框架 API 别从注解语义讲起：用"被调方 Controller ↔ 调用方接口逐行对照" + "curl URL 拆成注解"，给填空骨架让他自己填，不甩完整实现。

## 二、数据与代码原则
- 字段是否存在 / 是否合理只看后端（实体、表、DTO、写权限、Converter、聚合边界），禁止用前端引用次数判死字段。
- 禁止 mock / 假数据；前端展示的数据必须由后端从真实数据库查询返回。
- 链路：前端 → 后端 → 数据库单向；全链路命名一致；DTO 传输业务数据，不用 Map 承载。
- 未明确要求时，不擅自跑测试、不改启动配置、不启动后端服务。
- 读不到的数据返回 unavailable + 人话说明，绝不返回假数。
- AI 是协审层不替代人决策；结论标注 `source=rule|llm`，不把规则结果伪装成模型结论。

## 三、本机环境（安装后按实际填写）
- JDK：保留原路径即可 / 或改为本机实际路径。
- 构建工具本地仓库：确认不是默认的 `~/.m2`（若项目有自定义仓库，务必写对）。
- Windows + Git Bash 常见坑：
  - curl 测 localhost 必须 `--noproxy '*'`，否则被系统代理拦成 502。
  - psql 查询不能带中文（GBK 发送报无效 UTF8）：条件用 ASCII + `PGCLIENTENCODING=UTF8`。
  - esbuild 报 winmm.dll：复制到浅层路径并用 `ESBUILD_BINARY_PATH` 指向；工作目录须是项目根。
  - PowerShell 不回显 stdout；常驻进程用后台运行 + netstat / HTTP 探测。
- Unix 时间戳不要心算，用 `date` 或 `[DateTimeOffset]` 取。

## 四、工作习惯
- 手上常有大堆未提交改动：动刀前先 commit 固化 wip 快照，改完才能单文件回滚、分清"谁的改动"。
- 提交自己那部分别无脑 `git add -A`，逐个核对 `git status --short` 只 add 自己的。
- 实质改动后落记忆 + 跑对应验证（前端 `npx tsc --noEmit` / eslint，后端 `mvn compile`），通过才算完成。
- 厌恶构建产物目录堆积：构建直接覆盖 `dist`，不留 `dist_old_*` 副本。

## 五、维护约定
- 新增跨项目稳定偏好 → 追加到本文件对应章节；项目专属发现 → 回写该项目记忆。
- 本文件有字符上限，保持精简；膨胀时压缩旧条目，只留结论不留过程。
- 日期标注变更，便于追溯。
